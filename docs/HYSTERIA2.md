# Hysteria 2 直连节点：技术说明

本文记录 `000 | Hysteria 2 直连` 节点为什么打开新网页明显更快、它是怎么部署的，以及当时验证和测量的方法。部署命令和日常操作见[部署文档](DEPLOYMENT.md#可选的-hysteria-2-直连)，Cloudflare 节点的对应改造见 [CDN 节点的 XHTTP 长连接](XHTTP_LONG_CONNECTIONS.md)。

## 一句话结论

HY2 节点快，主要不是因为“下载带宽大”，而是因为：

1. **一直复用同一条 QUIC 长连接。** 客户端和服务器之间只建一次 QUIC 连接，之后每打开一个网站、每个新的 TCP 请求，都只是在这条连接里新开一个“流”（stream），不需要再做 TCP 握手、TLS 握手和协议握手。
2. **跑在 UDP 上，对丢包不敏感。** 实测出国链路丢包约 20%–27%。TCP 遇到丢包要等重传，一个包丢了，后面的数据全部排队等待；QUIC 每个流各自重传，一个网页的丢包不会卡住其他网页。
3. **拥塞控制更激进。** Hysteria 2 自带拥塞控制（未指定带宽时为 BBR，客户端填写带宽后为 Brutal 固定速率），丢包时不会像普通 TCP 那样大幅降速。

所以：同样的线路，旧的 Trojan + WebSocket 节点每开一个新网页要付出“多次往返 + 可能丢包重传”的代价（常常 1–3 秒），而 HY2 只需要一次往返就能开始传数据。

## 连接过程对比

旧方式（每个新网页都要走一遍）：

```text
客户端 ──TCP 三次握手──▶ 入口        1 个往返（丢 SYN 要等约 1 秒重传）
客户端 ──TLS 握手──────▶ 入口        1–2 个往返
客户端 ──WebSocket 升级─▶ 服务器      1 个往返
客户端 ──Trojan 请求────▶ 服务器 ──▶ 目标网站
```

HY2 方式：

```text
第一次：客户端 ──QUIC 握手 + 认证──▶ 服务器（只做一次）
之后每个新网页：在已有连接上开一个新流 ──▶ 服务器 ──▶ 目标网站（0 次额外握手）
```

网站自身的 HTTPS 握手（浏览器和 Google、YouTube 之间）在两种方式下都存在，这部分无法省掉；HY2 省掉的是“客户端到代理服务器”这一段的握手。

## 部署方式

实现代码在 [deploy/hysteria2.py](../deploy/hysteria2.py)，订阅生成在 [app/generator.py](../app/generator.py) 的 `render()`。

| 项目 | 设置 | 说明 |
|---|---|---|
| 程序 | 官方 Hysteria `v2.13.0` 二进制 | 安装时校验 SHA256，安装到 `/opt/proxy-hysteria/hysteria` |
| 监听 | `0.0.0.0:443/udp`（可用 `--port` 修改） | 与 Xray 的 TCP 443 共用端口号，互不冲突 |
| 证书 | 复用管理域名的 Let's Encrypt 证书 | `sniGuard: strict`，只接受管理域名的 SNI |
| 认证 | 随机 32 字节密码 | 升级时保留，订阅链接不变 |
| ECH | 默认外层 SNI 为 `www.apple.com.cn` | 抓包看到的是外层域名，真实的管理域名加密在内层 |
| 访问控制 | 拒绝访问内网和保留地址 | 防止节点被用来访问服务器所在内网 |
| 服务 | `proxy-hysteria2.service`，以 `xray` 用户运行 | 只授予绑定低端口的权限，开机自启，异常自动重启 |

订阅中的节点格式：

```text
hysteria2://<密码>@<服务器公网 IP>:443/?sni=<管理域名>&ech=<ECH 公开配置>#000 | SG Hysteria 2 直连
```

几个要点：

- **只能直连源站。** Cloudflare 普通橙云只转发 HTTP(S)/TCP，不转发 HY2 的 UDP 会话，所以 HY2 节点的地址必须是服务器公网 IP，不能套优选 IP。
- **安全组要放行 UDP。** 云厂商安全组和主机防火墙都要允许对应的入站 UDP 端口。
- **可以先测再发布。** `enable --no-publish` 只启动服务，不写入订阅；确认客户端能连上后再执行 `enable`。
- **失败自动回滚。** 启用过程中服务没有在 6 秒内监听成功，就停掉新服务并恢复旧配置。

## 当时的验证方法

以下是判断“HY2 快在哪里”时使用的方法，之后排查也可以照做：

1. **分段测丢包。** 从本机分别 `ping` / `mtr` 路由器、国内骨干、Cloudflare 入口和服务器源站，看丢包从哪一段开始出现。结论是 WiFi 与国内链路基本 0 丢包，到香港 Cloudflare 入口约 20%，到菲律宾源站约 27%。
2. **测“新连接首字节”而不是下载速度。** 每次都用一个全新的连接请求一个小页面（例如 `https://www.google.com/generate_204`），记录从发起到收到第一个字节的时间。这个数值对应“打开新网页要等多久”。
3. **测并发打开。** 同时打开 6 个不同网站，记录全部返回首字节的时间，模拟浏览器打开一个新页面时同时访问多个域名的情况。
4. **取中位数，多轮重复。** 丢包很不稳定，同一节点不同轮次可能相差一倍，只比较同一轮里的相对差距。
5. **不动本机代理。** 测试时用独立的 Xray / Hysteria 核心按订阅链接生成配置，监听另外的本地端口，并绑定物理网卡，不影响正在使用的 v2rayN 和虚拟网卡。

参考数据（2026-11-12，菲律宾服务器，本机移动网络，中位数）：

| 节点 | 新连接首字节 | 同时开 6 个站 | 丢包约 20% 时的稳态下载 |
|---|---:|---:|---:|
| HY2 直连 | 669 ms | 1086 ms | 约 20 Mbps |
| Trojan + WebSocket（香港 Cloudflare 入口） | 1056 ms（早先几轮 1.6–2.3 秒） | 3694 ms | 约 0.5 Mbps |

## 局限

- 依赖 UDP：部分网络（公司网、部分运营商时段）会限速或屏蔽 UDP，这时 HY2 会变慢甚至连不上，需要换回 CDN 节点。
- 依赖源站 IP：HY2 直接暴露服务器 IP，IP 被封后只能换 IP 或使用 CDN 节点。
- 只有部分客户端支持：v2rayN、v2rayNG 等支持 `hysteria2://`；Clash/Surge 订阅不包含此节点。忽略 ECH 参数的客户端仍可连接，但握手中会显示管理域名。
